# Schemas — actions, traits, effect ops

Complete field reference for `data/player_actions.yaml`, `data/traits.yaml` and
the shared effect grammar. The narrative guide is in `../SKILL.md`.

---

## 1. `data/player_actions.yaml`

One entry per engine action, keyed by `ActionId`. English keys, display strings
as `Locale` objects (`{ fr, en? }` — `en` falls back to `fr`).

### Identity & link to the card

| Field | Required | Meaning |
|---|---|---|
| `vaultCard` | yes in practice | id of the French card in `rules/fr/cartes/*.yaml`. **The coherence test reads it** — an action without it fails. |
| `vaultOption` | no | id of the *option* on that card, when the card carries several playable units (`deplacement` → `course`). A card is *material*, an action is a *rule*: the link is not 1↔1. |
| `name` | yes | `Locale`. Must equal the card's `nom`. |
| `description` | yes | `Locale`. One-line tactical summary; injected into LLM agent prompts. |

### Timing & cost

| Field | Meaning |
|---|---|
| `initiative` | 1–9. Fixes the **band**: I = 1–3 🌓 · II = 4–6 🌕 · III = 7–9 🌗. Must equal the card's. |
| `cost.actions` | PA ⚫. Must equal the number of moons on the card. |
| `cost.fatigue` | 💧 paid as a cost (not damage). Must equal the 💧 count on the card. |
| `cost.reactions` | ⚡. Non-zero only for reactions. Must equal the ⚡ count on the card. |
| `cost.endPlayerRound` | ends the combatant's round (🔴). Default `false`. |

### Conditions of use

| Field | Meaning |
|---|---|
| `prerequisite` | `{ skill, minValue }` — a skill rank gate. |
| `mentalConditions` | list of `MentalState` in which the action is usable. **Empty/absent = no constraint** (the common case). |
| `requiresFirstAction` | 🟢 — must be the round's first action. |
| `blockedByStatus` | statuses that forbid it (Course ← `winded`, `knockdown`, `kneeling`, `entrapped`). |
| `requiresInertia` | minimum élan ➡️ (Charge = 3) — forces a Course in an earlier band. |

### Space

| Field | Meaning |
|---|---|
| `reach` | max distance in cases (1 = adjacent). **Absent = ungated** (social actions have no stated shouting distance). Temporary: reach really belongs to the *weapon*. |
| `effectiveRange` | synonym of `reach` for ranged actions; both map to `ActionDef.reach`. |
| `minRange` | minimum distance. `minRange: 1` = the target must be strictly farther than 1 case (a bow does not fire when engaged). Gated in normal play **and** in reactions. |

### Movement

| Field | Meaning |
|---|---|
| `movement: true` | no roll, no guard — routed to the movement branch of `resolvePlans`. |
| `moveBudget` | `N`, or `{ base: N, addSkill: <skill> }` (Course = 5 + Mobilité). |
| `grantsInertia` | élan ➡️ laid down on resolution (Posture 1, Marche 2, Course 3). |
| `grantsStatus` | status the action inflicts on itself. |
| `clearsStatus` | status it always removes — **declarative, for the planner** (a Band-I Respiration reopens a Band-II Course). |

### Reaction

| Field | Meaning |
|---|---|
| `trigger.on` | `movement-initiated` · `heavy-wound-taken` · `phase-start` · `targeted-vs-guard`. **Presence makes the action a reaction**: excluded from planning, from the offensive envelope, from the reach profile. |
| `trigger.scope` | `reach` (default — the action's own reach) or `adjacent` (1 case). `self` is **not supported**: `eligibleReactions` filters on opposing factions. |

### Resolution — pick exactly one

**Declarative** (preferred): `onSuccess` / `onFailure` are required, `onCritical`
and `onFlaw` are optional and **additive** to the base tier. Each is
`{ text: Locale, effect: [ops] }`. `resolve()` is generated by `makeResolve`.

**Custom**: `resolver: <id>` referencing `ACTION_RESOLVERS`
(`simulator/src/combat/action-resolvers.ts`), which supplies both `getDC` and
`resolve`. Reserved for dynamic amounts and unconditional effects (Respiration,
Stabiliser, the four mental consolidations).

### Other

| Field | Meaning |
|---|---|
| `selfTargeted` | rolls against a dynamic DC, no opponent, no guard. |
| `selfAdvantage` | 🟩 the action grants itself (Charge is "avec 🟩"). |
| `roll` | `{ characteristic, skill }`. Movement actions have no roll — give a nominal pair, it is never read. |
| `tags` | see §3. |

## 2. `data/traits.yaml`

```yaml
traits:
  <id-kebab-fr>:
    name:   { fr: "…" }
    kind:   active | passive        # ⚒️ active modifies a named action · ♾️ passive
    skill:  <sim skill id>          # the skill that unlocks it (ranks 3 and 5)
    action: <ActionId>              # ⚒️ only; may name an action the sim lacks
    effect: { fr: "…" }             # prose, NEVER parsed
    grants: { … }                   # ABSENT = prose-only, no engine hook
```

**No `rank` field.** The vault does not say which trait comes at rank 3 and
which at 5, and several skills offer three traits for two slots — the player
chooses. Validation derives the ceiling instead:
`traitsTaken(skill) ≤ (rank ≥ 3 ? 1 : 0) + (rank ≥ 5 ? 1 : 0)`.

### Grant families

| Family | Shape | Effect | Implemented |
|---|---|---|---|
| `reactiveMode` | `{ on, scope?, cost: { actions?, reactions?, fatigue? } }` | **Adds** a reactive variant of `action`: the base def gains a `trigger` and the given cost **replaces** the original. The action stays planned normally. | ✅ |
| `costDelta` | `{ actions?, reactions?, fatigue? }` | Signed deltas on `action`'s cost, floored at 0. Nothing else changes — same outcomes, same initiative. | ✅ |
| `rollBonus` | `{ advantages?, rerolls?, skillBoosts? }` | Dice modifiers. The four primitives already exist in `RollParams`; the seam is `traitRollMods` in `combat/traits.ts`, to be called from `checkRollParams` / `makeGuardRoll`. | ✗ specified |
| `guardMod` | `{ cost?, grantsStatus? }` | A guard's cost and backlash (Esquive plongeante, Garde écrasante). Seam: `traitGuardMods`. | ✗ specified |

### Skill vocabulary drift

The simulator and the web do not name three skills alike. `web/src/lib/traits.ts`
translates at the entry point; `data/traits.yaml` uses the **simulator** names.

| Simulator | Web | French |
|---|---|---|
| `robustness` | `toughness` | Robustesse |
| `composure` | `presence` | Prestance |
| `foresight` | `clairvoyance` | Clairvoyance |

To be resolved by the "fusion des structures de personnage" chantier (the web
vocabulary is the target). Do not fix it piecemeal.

## 3. Card tags (`CardTag`)

A free **set**, shared by player actions and adversary cards. The engine reads
tags rather than inferring intent from effects. Three loose groups:

- **intent** — `offensive` · `defensive` · `movement` · `support` · `healing` · `enhancement`
- **domain** — `melee` · `ranged` · `mental` · `physical` · `social`
- **effect marker** — `physicalDamage` (💢/💔) · `mentalDamage` (🔻🔺 or ◇ loss) · `fatigueDamage` (💧 inflicted)

Taxonomy documented in `rules/fr/cartes/README.md`. Example: Charge =
`[offensive, movement, melee, physical, physicalDamage]`.

## 4. Effect ops (`EffectOp`)

The ONE vocabulary shared by player action outcomes and adversary cards
(`simulator/src/combat/effect-ops.ts`). Target-directed unless marked SELF;
SELF ops are silently dropped when the caller has no `selfId`.

| Op | Effect |
|---|---|
| `{ wound: N }` | 💢 N light wounds |
| `{ heavyWound: N }` | 💔 N heavy wounds |
| `{ fatigue: N }` | 💧 N fatigue on the target |
| `{ selfFatigue: N }` | SELF — 💧 on the actor (⚠️ Maladresse) |
| `{ status: S }` | apply a `StatusEffect` |
| `{ mental: ±N }` | shift the mental track: −N = 🔻 vers Peur, +N = 🔺 vers Colère |
| `{ shiftIfBroken: ±N }` | same, but **only once the target's ◇ is spent** |
| `{ drainStability: N }` | remove N ◇ from the target |
| `{ gainStability: N }` | SELF — gain N ◇ |
| `{ destabilize: true }` | target skips its next ◇ regain |
| `{ move: N }` | SELF — the actor closes on the target, up to N cases (an *intent*; the resolver builds the path) |
| `{ setInertia: N }` | SELF — set élan ➡️ (Charge consumes it → 0) |

Statuses (`StatusEffect`): `winded` 😮‍💨 · `stunned` 💫 · `knockdown` 🙏 ·
`kneeling` 🧎 · `hemorrhage` 🩸 · `entrapped` 🕸️ · `incapacitated` · `near-death`.

## 5. Cost ↔ card encoding

The test counts symbols in the card's `cout:` string:

| Symbol | Counts as |
|---|---|
| 🌓 / 🌕 / 🌗 | 1 PA each (`cost.actions`) — **and the moon must match the initiative's band** |
| 💧 | 1 `cost.fatigue` |
| ⚡ | 1 `cost.reactions` |

Coloured PA (🟢⚫🔴) are **no longer** part of the cost string: the initiative
bands replaced them. "First action" is now `requiresFirstAction`, not a cost.

## 6. Registration points that do not derive themselves

Everything else is read from the YAML. These are the ones to remember:

1. **`ActionId`** in `simulator/src/combat/types.ts` — a new action's key is cast,
   so omitting it compiles but breaks every literal reference.
2. **`allowedActions`** in `simulator/encounters/*.yaml` — an action in no kit is
   never exercised.
3. **`ACTION_LABELS`** in `web/src/lib/combat-labels.ts` — *fallback only*
   (plan lists, the 🧠 badge). Real cards resolve through `vaultCard`.
4. **A bearer sheet** for a trait (`simulator/characterSheets/*.yaml`) — and
   prefer a new sheet over bumping a reference profile's skill rank.
